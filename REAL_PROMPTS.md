# Промпты по этапам: тип REAL

Временный файл для Mart. Открываешь новую сессию → копируешь промпт очередного
этапа → сессия выполняет этап целиком и отмечает его в `PLAN_REAL.md`.

**Один этап = одна сессия = один коммит.** Промпты идут строго по порядку:
каждый следующий опирается на то, что предыдущий уже в коммите.

Оценка: этап 1 — небольшой, **этап 2 — самый крупный, под него нужна свежая
сессия целиком**, этап 3 — средний, этап 4 — средний, но требует ручного счёта
ожидаемых значений для `.expected`.

По завершении этапа 4 этот файл и `PLAN_REAL.md` удаляются — существенное
переезжает в `CLAUDE.md`.

---

## Этап 1 — лексер, AST, парсер

```
Проект st2c, начинаем реализацию типа REAL. Прочитай CLAUDE.md и PLAN_REAL.md.

Выполни этап 1 из PLAN_REAL.md целиком: ключевое слово REAL и вещественный
литерал в лексере (readInt → readNumber по грамматике IEC, с откатами),
узел RealLiteral в AST, ветки в parsePrimary и parseType, плюс тесты лексера и
парсера. Все детали и подводные камни — в PLAN_REAL.md, раздел «Этап 1».

После этапа объявление `x : REAL;` всё ещё обязано давать ошибку sema
`unknown type "REAL"` — это правильное промежуточное состояние.

Рабочий стиль по CLAUDE.md: go build ./... и go vet ./... чисто, go test ./...
зелено; golden-эталоны не перегенерировать (этап 1 их менять не должен).

По завершении отметь этап в PLAN_REAL.md — чек-лист и журнал сессий — и
закоммить всё одним коммитом. Этап 2 не начинай.
```

## Этап 2 — слой типов в sema

```
Проект st2c, реализуем тип REAL, этап 1 уже в коммите. Прочитай CLAUDE.md и
PLAN_REAL.md.

Выполни этап 2 из PLAN_REAL.md целиком — это ядро работы: enum TypeKind,
вывод типов выражений снизу вверх (typeOf + hintOf) вместо нынешнего
targetType-string, side-table sema.Info, новые проверки (совместимость при
присваивании, BOOL в условии IF, только INT в FOR, типы аргументов, резолв
ReturnType), встроенные конверсии INT_TO_REAL/REAL_TO_INT и смена контракта
Check → (*Info, []error) с правкой main.go и тестов. Все детали — в
PLAN_REAL.md, раздел «Этап 2».

Codegen на этом этапе только приводится в компилируемое состояние под новый
контракт — REAL в C он ещё не умеет, это этап 3.

Рабочий стиль по CLAUDE.md: go build ./... и go vet ./... чисто, go test ./...
зелено; существующие golden-эталоны меняться не должны.

По завершении отметь этап в PLAN_REAL.md — чек-лист и журнал сессий — и
закоммить всё одним коммитом. Этап 3 не начинай.
```

## Этап 3 — codegen

```
Проект st2c, реализуем тип REAL, этапы 1 и 2 уже в коммитах. Прочитай CLAUDE.md
и PLAN_REAL.md.

Выполни этап 3 из PLAN_REAL.md целиком: REAL → float в cTypes, эмиссия
литералов (адаптивный целый литерал в REAL-контексте по side-table, cFloatLit
с суффиксом f), zeroLiteral вместо литерального 0 в трёх местах, формат %g в
драйвере -main, конверсии INT_TO_REAL/REAL_TO_INT со static-хелпером
округления, эмитируемым только при фактическом использовании. Все детали — в
PLAN_REAL.md, раздел «Этап 3».

Важная проверка этапа: golden .c всех одиннадцати существующих примеров обязаны
остаться побайтово прежними. Прогони

    go test ./src/codegen -update && git diff --stat src/codegen/testdata

и убедись, что diff пуст. Если что-то изменилось — ошибка в правке, а не в
эталонах.

Рабочий стиль по CLAUDE.md: go build ./... и go vet ./... чисто, go test ./...
зелено.

По завершении отметь этап в PLAN_REAL.md — чек-лист и журнал сессий — и
закоммить всё одним коммитом. Этап 4 не начинай.
```

## Этап 4 — корпус, тесты, документация

```
Проект st2c, реализуем тип REAL, этапы 1-3 уже в коммитах. Прочитай CLAUDE.md и
PLAN_REAL.md.

Выполни этап 4 из PLAN_REAL.md целиком: новый пример examples/real_all.st,
эталоны (real_all.ast, real_all.c, real_all.expected + имя в goldenExamples),
табличные тесты sema TestReal, и обновление CLAUDE.md — статус, MVP-ограничения,
разделы по пакетам, новые архитектурные решения, снятые и добавленные долги.
Все детали — в PLAN_REAL.md, раздел «Этап 4».

Ожидаемые значения в real_all.expected посчитай вручную и покажи мне расчёт: они
печатаются через %g (6 значащих цифр), поэтому в примере бери величины, точные в
двоичном представлении (0.5, 0.25, 2.5).

Прогони проверки из раздела «Верификация» PLAN_REAL.md — включая полную цепочку
через gcc и негативные случаи через stdin.

Этим же коммитом удали PLAN_REAL.md и REAL_PROMPTS.md: работа закрыта,
существенное переехало в CLAUDE.md.

Рабочий стиль по CLAUDE.md: go build ./... и go vet ./... чисто, go test ./...
зелено; diff новых golden-эталонов просмотреть глазами.
```
