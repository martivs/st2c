## Цель и границы

Добавить пять конструкций по всей цепочке lexer → parser → AST → sema → C:

- CASE с INT-селектором, одиночными метками, списками, диапазонами и ELSE;
- RETURN; в FUNCTION, FUNCTION_BLOCK и PROGRAM;
- целочисленный MOD;
- возведение в степень ** с явно определённым контрактом типов;
- унарный + для чисел.

Не входят: CONTINUE, новые типы, массивы, структуры, именованные константы
в CASE, общая свёртка констант, стандартная библиотека PLC, восстановление
парсера после ошибок, реорганизация каталогов, исправление старых долгов.
Go — только стандартная библиотека. Выход — C99; GCC-расширения и goto запрещены.
Синтаксический AST и side-table sema.Info сохраняются.

## Что происходит с техническим долгом

Старые дефекты не исправляются автоматически от появления операторов.
Они остаются отдельной работой. Но обещать неизменный «объём долга» нельзя:
новые конструкции взаимодействуют с существующими ограничениями. Критерий
приёмки здесь — отсутствие регрессий и новых известных дефектов в заявленных
возможностях новых операторов, а не неизменное число строк списка долгов.
Отсутствие MOD и **, напротив, перестанет быть ограничением после реализации.

Базовый список отложенного (включая находки обзора 2026-11-02):

1. PROGRAM/ФБ: инициализатор a := b может прочитать b до его обнуления.
2. Коллизии глобальных C-имён: P вместе с P_init; switch вместе со st_switch;
   ранее записанное затенение вызываемой функции локальной переменной.
3. REAL_TO_INT: 0.49999997 даёт 1; правило половин «от нуля» отличается
   от описанного IEC-округления к ближайшему чётному. Старые эталоны не менять.
4. Промежуточное signed overflow в C: при a=30000 выражение a*a*a
   переполняет int до присваивания в int16_t. Формулировка «всё обрезается
   при присваивании» не является общей гарантией wrap-around.
5. CONSTANT допускает запись; VAR_TEMP PROGRAM/ФБ сохраняется между сканами;
   RETAIN игнорируется; VAR_IN_OUT не имеет семантики передачи по ссылке.
6. Нулевой шаг FOR может повесить программу; нет watchdog, общей защиты
   от деления на ноль, проверки всех выходов преобразований за диапазон.
7. Прочие долги и ограничения из AGENTS.md, включая позднюю диагностику
   отдельных конструкций в codegen и ограниченные сообщения парсера.

На этапе 1 перенести ещё не записанные находки в раздел долгов AGENTS.md,
не меняя реализацию. Сохранить их после удаления этого плана.
Непосредственные требования новых операторов — не старый долг: правильное
EXIT через CASE, корректный RETURN, уникальность новых служебных имён,
правила MOD и ** должны быть реализованы и проверены в этой работе.
Если старый дефект блокирует новый контракт, зафиксировать конкретное
воспроизведение и согласовать изменение границ; не чинить молча и не
переносить дефект новой возможности в старый долг ради закрытия этапа.

## Контракт: фиксированная часть

### MOD и унарный +

MOD — бинарный оператор над INT с результатом INT; REAL и BOOL запрещены.
Приоритет MOD равен * и /, ассоциативность левая. Контекст REAL не превращает
его операнды в REAL: `r := 5 MOD 2` не должен молча стать REAL-операцией.
Знак ненулевого остатка — знак делимого: -7 MOD 3 = -1, 7 MOD -3 = 1.
Политику нулевого делителя закрепить на этапе 1, не расширяя её на старое /.

Унарный + — отдельный ast.Op, принимает INT/REAL, сохраняет тип и
адаптивность литерала, BOOL отвергает. Приоритет соответствует существующим
унарным - и NOT. Не терять знак в AST. `+32768` в INT-контексте — ошибка;
`-32768` остаётся законным. Предельные случаи комбинаций знаков проверить
без попытки добавить общую свёртку констант.

### RETURN

Синтаксис только `RETURN;`, без выражения; точка с запятой обязательна.
В FUNCTION возвращается текущее значение переменной результата, в PROGRAM
и ФБ завершается текущий вызов `_step` / `_body` через `return;`.
Выход не сбрасывает состояние и не завершает процесс или дальнейшие сканы.
Вызвавший ФБ код продолжает выгрузку выходов (`=>`) и следующие операторы.
RETURN допустим на любой глубине IF/циклов/CASE, не требует наличия цикла.
Возврат до присваивания результата сохраняет текущую нулевую инициализацию.
Общий анализ достижимости и обязательности присваивания результата не вводить.

### CASE

Форма: `CASE expr OF label-list: statements ... [ELSE statements] END_CASE[;]`.
Селектор — INT-выражение, вычисляется ровно один раз. Выполняется одна ветка;
нет совпадения — ELSE либо ничего. Проваливания между ветками нет.
Не менее одной помеченной ветки; пустое тело ветки и пустой ELSE допустимы.

Метка — десятичный целый литерал с необязательным одиночным + или -;
список разделяется запятыми; включительный диапазон записывается `low..high`.
Все границы должны помещаться в INT, включая -32768. Запрещены обратные
диапазоны, дубли и любые пересечения меток одного CASE, в том числе внутри
одного списка. Одинаковые метки в разных вложенных CASE законны.
Имена, вызовы, BOOL/REAL и произвольные выражения в метках не поддерживаются;
выдавать понятную ошибку, не игнорировать.

Новые ключевые слова CASE, OF, END_CASE, RETURN, MOD регистронезависимы;
CASE1, RETURNED, MODEL и другие длинные идентификаторы остаются IDENT.
Сохранить разбор `1..5` без ошибочного REAL-литерала и `inst.Out`.

CASE не увеличивает глубину циклов sema: EXIT внутри CASE без внешнего цикла
остаётся ошибкой. Для C-switch EXIT должен пройти все промежуточные switch
до ближайшего цикла ST через флаги выхода; goto запрещён.
EXIT из цикла внутри ветки CASE завершает только этот внутренний цикл.
Решение должно пропускать весь остаток покидаемого тела, а не только выйти
из самого внутреннего switch.

## Решения, обязательные на этапе 1

Профиль — IEC 61131-3:2013 в национальной редакции ГОСТ Р МЭК
61131-3-2016, §6.6.2.5.8 (MOD и EXPT), §7.3.2, таблица 71
(приоритеты и равенство приоритетов). Для EXPT стандарт задаёт
вещественное основание, числовой показатель и тип основания для результата.
Политика аварии и адаптация литералов ниже принадлежат st2c.
[Текст стандарта](https://meganorm.ru/mega_doc/norm/gost_r_gosudarstvennyj-standart/15/gost_r_mek_61131-3-2016_natsionalnyy_standart_rossiyskoy.html)

### 1. Степень и вывод типов

| Тип основания после вывода | Показатель INT | Показатель REAL |
|---|---|---|
| REAL | REAL | REAL |
| INT | REAL (расширение) | REAL (расширение) |

В расширении st2c целое основание точно представляется в float для всего
INT16. Расширение локально для **. BOOL и экземпляр ФБ недопустимы с любой
стороны. Результат всегда REAL, включая инициализатор и вызов; для
присваивания INT нужна явная конверсия. Внешний want результата этого не меняет.

Согласованное правило генерации C зависит от типа основания в `Info.Types`.
Для `n : INT` в выражении `n ** 2` хелпер получает `(float)n` с явным
приведением. Для `r : REAL` в `r ** 2` хелпер получает непосредственно `r`,
поскольку тип переменной в C уже `float`. Проверить обе формы в эталоне C.

Основание без подсказки получает want=Real, включая знаки и арифметику
из одних литералов: (1/2)**2 = 0.25. У показателя независимый вывод без
подсказки от основания или назначения: 2**(1/2) = 1, 2**(1.0/2) —
квадратный корень из двух. Целый литерал показателя проверяется как INT
(32768 — ошибка, 32768.0 допустим). hintOf для степени всегда Real,
для MOD — Int; typeOf записывает также типы операндов, без повторного вывода.

От сильного к слабому: постфиксы, унарные + / - / NOT, **, затем * / MOD.
Степень левоассоциативна. Приоритетный разбор даёт (2**3)**2 = 64,
(-2)**2 = 4 для -2 ** 2, 2**(-2) = 0.25, 2*(3**2) = 18.
Скобки меняют деревья: 2**(3**2) = 512, -(2**2) = -4.
Унарный плюс — узел дерева и тождественная операция над числом;
+(-32768) законно, +32768 и -( +32768 ) в INT-контексте отвергаются
на положительном литерале; прежний случай --32768 не переоткрывается.

### 2. Числовые границы

MOD вычисляет каждый INT-операнд один раз, результат INT. Для любого
делителя 0 (литерала или вычисленного) результат 0. Иначе остаток C99
после усечения частного к нулю. В хелпере выполнять % в int32_t после
проверки нуля; -32768 MOD -1 даёт 0 даже на C с 16-битным int.

Степень для конечных входов: x**0 = 1, включая 0**0; ноль с положительной
степенью даёт ноль. Отрицательная степень поддерживается (2**-3 = 0.125).
Отрицательное основание принимает целочисленный **по значению** показатель
((-2)**3.0 = -8, (-2)**-2 = 0.25). Нулевое основание с отрицательным
показателем, отрицательное с дробным, неконечный вход или переполнение
результата float — ошибка исполнения. Хелпер выдаёт в stderr сообщение
с оператором ** и причиной (область определения или диапазон), затем
завершает процесс с EXIT_FAILURE. Округление очень малого конечного результата
до subnormal/нуля допустимо. Типы и представимость самих литералов проверяет
sema; значение операции, даже между литералами, проверяется при исполнении.
Нет общей свёртки или диагностики ошибки в пропущенной ветви.

### 3. Генерация числовых операций

Для ** — static-хелпер над float с powf из math.h. До вызова проверить
isfinite входов, ноль, знак и целочисленность показателя через truncf(y)==y
(без приведения к INT); конечный результат проверить isfinite. На целевой
платформе проекта REAL — binary32, сборка без fast-math. Сохранить вычисление
операндов новых операций слева направо и ровно один раз, включая вложенные
вызовы и инициализаторы (раздельные присваивания во временные переменные;
не полагаться на порядок аргументов C). Вычисление остаётся в исходной
ветви и на каждой проверке условия цикла; сохранить короткое замыкание
AND/OR даже при ошибке в правом операнде. Хелперы и новые заголовки только
при фактическом использовании соответствующей операции. С ** команда GCC
и в TestGCC, и для ручного запуска: `gcc -std=c99 -Wall -Wextra out.c -lm -o out`.
Без ** прежняя команда. Проверки границ дополнительно с
`-fsanitize=undefined -fno-sanitize-recover=all`.

### 4. CASE

В отдельном блоке сохранить селектор один раз. С одними точками — switch
по селектору, последовательные case для списка. Если есть хотя бы один
диапазон — номер ветки изначально 0 (нет совпадения); цепочка if/else if
по ветвям в порядке текста, внутри объединить проверки точек (==) и
закрытых интервалов (>= и <=) через ||. Совпадение получает номер 1..N.
Затем switch по номеру, один case на тело, default для ELSE.
Каждое тело в фигурных скобках, в том числе пустое, с завершающим break.
Размер C пропорционален числу меток и тел. Sema обрабатывает каждую метку
как закрытый интервал, точки как [n,n]; проверяет min/max и порядок раньше
пересечения. Сравнивать с ранее принятыми интервалами данного CASE в порядке
текста, сообщить позиции новой и первой конфликтующей метки; ошибочную
метку не добавлять, проверку остальных меток и тел продолжать.

### 5. EXIT и имена

На входе в каждый POU пустой стек циклов и switch. Для каждого EXIT найти
ближайший цикл и отметить все switch между EXIT и этим циклом. IF и блоки
не перехватывают break. Циклу с отмеченным путём нужен один собственный
int-флаг, инициализированный нулём перед каждым входом в цикл. Без switch
на пути — обычный break. Иначе EXIT выставляет флаг и выполняет break;
сразу за каждым отмеченным switch, **до следующего оператора**, проверка
этого флага выполняет break из следующего switch либо из целевого цикла.
Внутренний цикл ограничивает поиск, чужой флаг не трогает. RETURN во всех
случаях идёт прямо из текущего POU. Состояние генерации сбрасывается
между POU, флаги не хранятся в struct.

После mapName собрать занятые C-имена всех POU, typedef, производных
_init/_step/_body, параметров, переменных, полей и уже существующих временных.
Новые имена (например st2c_pow, st2c_mod, st2c_sel, st2c_arm, st2c_exit)
выделять в порядке исходника с первым свободным числовым суффиксом,
сверяя **конечное** написание и немедленно резервируя. Глобальные хелперы
не должны затеняться ни в одном POU. Новые стандартные имена из подключаемых
заголовков (включая функции и макросы, например powf, truncf, isfinite,
exit) защитить при выводе пользовательских имён в затронутом файле;
для переименования использовать тот же поиск свободного имени. Включить
тест с powf и st_powf одновременно. Старые пары конфликтующих имён
за пределами новых операций остаются отдельным долгом.
