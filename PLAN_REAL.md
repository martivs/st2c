# План: тип REAL (временный документ)

Рабочий план реализации типа `REAL` в st2c. **Временный**: по завершении
этапа 4 удаляется вместе с `REAL_PROMPTS.md`, существенное переезжает в
`CLAUDE.md` — так же, как это было сделано с `PLAN-2026-08-07.md`.

Этот файл — источник контекста для каждой новой сессии: этап читается отсюда,
результат отмечается здесь же, в том же коммите, что и код этапа.

**Один этап = одна сессия = один коммит.** Следующий этап не начинать без
явного «переходим дальше» от Mart.

## Зачем

Сейчас `INT` — единственный скаляр языка, и тип в проекте не является
сущностью: он носится строкой (`sema.Symbol.TypeName`, `codegen.varInfo.stType`),
а sema проверяет значения только «сверху вниз» — параметр `targetType string`
в `checkExpr` (`src/sema/sema.go:238`). Вывода типов снизу вверх нет, проверок
совместимости типов нет ни одной, `checkIntRange` при целевом типе, отличном от
INT, молча выходит (`src/sema/sema.go:604-611`).

Пока скаляр один, это непротиворечиво. Второй скаляр модель ломает: без вывода
типов `i := r;` молча усечётся, `r := 1/2;` молча даст 0 (целочисленное
деление), `r := i + r;` пройдёт по правилам C. Поэтому REAL — не «ещё одна
строка в `cTypes`», а повод построить слой типов, который дорожная карта
`CLAUDE.md` и так предусматривает.

Результат по завершении: `REAL` объявляется, считается и печатается; смешение с
`INT` диагностируется sema и переводится только явными `INT_TO_REAL` /
`REAL_TO_INT`; условие `IF` обязано быть сравнением (BOOL); `FOR` остаётся
целочисленным.

## Принятые решения (не переоткрывать)

1. **Слой типов, строго.** Свой enum типов в sema, вывод снизу вверх,
   side-table, запрет неявных смешений INT и REAL.
2. **Адаптивный целый литерал.** Литерал принимает тип контекста: `r := 0;`
   законно, `r := 1 / 2;` — вещественное деление (0.5), codegen эмитит
   `(1.0f / 2.0f)`. Принятый литералом тип хранится в side-table.
3. **`REAL` → `float`** (IEC: REAL — 32 бита), литералы с суффиксом `f`;
   `LREAL` → `double` остаётся свободным на будущее.
4. **Конверсии с округлением по IEC.** `INT_TO_REAL` → `(float)`,
   `REAL_TO_INT` → сгенерированный static-хелпер с округлением к ближайшему.
   Без `<math.h>` и `-lm`: `TestGCC` компилирует без `-lm`
   (`src/codegen/codegen_test.go:129-130`), и `lroundf` не слинкуется.
5. **`FOR` остаётся целочисленным.** У REAL нет широкого счётчика решения 6, а
   накопление ошибки шага делает число итераций непредсказуемым.
6. **Условие `IF` обязано быть BOOL** (результатом сравнения). Проверено: все
   условия в `examples/*.st` — сравнения, регрессии корпуса нет.

## Этап 1 — лексер, AST, парсер

**Цель:** `REAL` и вещественный литерал доходят до sema. После этапа объявление
`x : REAL;` всё ещё даёт ошибку sema `unknown type "REAL"` — это корректное
промежуточное состояние, тесты остаются зелёными.

### `src/lexer/lexer.go`

- Новый `TokenType REAL_LIT`. **Обязательно добавить его в `tokenNames`
  вручную** (`lexer.go:65-73`): `init()` заливает туда только ключевые слова,
  иначе `String()` вернёт `UNKNOWN` в сообщениях парсера.
- Ключевое слово `REAL`: константа в enum + строка в `keywords`
  (`lexer.go:88-97`) — `tokenNames` заполнится сам.
- `readInt` → `readNumber` (`lexer.go:294-301`), грамматика IEC:
  `integer '.' integer [exponent] | integer exponent`.
  - дробная часть принимается, **только если после `.` идёт цифра** — иначе
    откат к `INT_LIT`. Это разводит `3.14` и `inst.Out`, а заодно оставляет
    рабочим будущий `ARRAY [1..10]`: в `1..10` после `1` идёт `.`, но за ней не
    цифра → `INT_LIT(1) DOT DOT INT_LIT(10)`;
  - экспонента принимается, только если за `e`/`E` идёт `[+|-]` цифра — иначе
    откат (`1EXIT` не должен съесть хвост);
  - `1.` без дробной части — не REAL (по IEC), лексится как `INT_LIT DOT`.

### `src/ast/ast.go`

- `RealLiteral{Value float64, Text string, Tok lexer.Token}` рядом с
  `IntLiteral` (`ast.go:381-389`). `Text` — исходное написание: `String()`
  печатает `Real(<Text>)`, чтобы golden `.ast` не зависел от того, как Go
  форматирует float.

### `src/parser/parser.go`

- `parsePrimary` (`parser.go:428-436`) — ветка `lexer.REAL_LIT` через
  `strconv.ParseFloat`, ошибка разбора по образцу существующей ветки `INT_LIT`.
- `parseType` (`parser.go:212-224`) — добавить `lexer.REAL` в `case` рядом с
  `lexer.INT`.

### Тесты этапа 1

- `lexer_test.go` — table-driven кейс: `3.14`, `1.0E3`, `1e-3`, `1..10`, `x.y`,
  `1.` (откат к `INT_LIT DOT`).
- `parser_test.go` — структурный кейс на вещественный литерал и на `: REAL` в
  объявлении переменной и в типе возврата функции.

## Этап 2 — слой типов в sema (ядро)

Основная работа — `src/sema/sema.go`. Самый крупный этап; под него нужна свежая
сессия.

### Тип как сущность

Enum `TypeKind`: `Invalid, Unknown, Int, Real, Bool, FBInst`. `Bool` —
внутренний тип результата сравнений; объявить `x : BOOL;` пока нельзя (это
отдельная задача). `Symbol` получает поле `Type TypeKind`; `TypeName string`
остаётся для текста сообщений об ошибках.

`builtinType(name) (TypeKind, bool)` — единственная точка «встроенные скаляры»
(`INT`, `REAL`); `resolveType` (`sema.go:108-123`) идёт через неё вместо
нынешнего хардкода `EqualFold(d.TypeName, "INT")`.

### Вывод типов

`checkExpr(e, targetType string)` заменяется на
`typeOf(e ast.Expression, want TypeKind) TypeKind` — возвращает выведенный тип
и **записывает его в side-table**:

- `IntLiteral`: `want == Real` → `Real`; иначе `Int` + прежняя проверка
  диапазона −32768..32767. Трюк с `NEG` над литералом для `-32768`
  (`sema.go:246-252`) сохраняется.
- `RealLiteral`: `Real` + проверка выхода за диапазон `float` (±3.4028235e38) —
  по образцу `checkIntRange`.
- `BinaryExpr`, арифметика: операнды одного типа, результат — он же.
- `BinaryExpr`, сравнение: операнды одного типа (`Int` или `Real`), результат
  `Bool`.
- `UnaryExpr NEG`: тип операнда; `Bool` — ошибка.
- `MemberExpr` / `CallExpr`: тип члена / `ReturnType` функции.

**`hintOf(e) TypeKind`** (~30 строк) — предварительный вывод типа без записи в
side-table и без выдачи ошибок; для выражения из одних литералов возвращает
`Unknown`. Нужен там, где `want` не приходит сверху: у операндов сравнения
(`IF 1 > r` и `IF r > 1` обязаны работать симметрично) `want` каждого операнда
берётся как `hintOf` соседа.

### Новые проверки

- присваивание — тип значения равен типу цели (`Bool` в цель нельзя);
- условие `IF` обязано быть `Bool` — вместо нынешнего
  `checkExpr(st.Condition, "INT")` (`sema.go:196-198`);
- `FOR` — переменная и `Start`/`End`/`Step` только `Int`;
- аргументы функций (`sema.go:323-341`) и входы ФБ (`sema.go:490`) — тип
  аргумента равен типу входа;
- `Function.ReturnType` наконец резолвится (`sema.go:149` сейчас кладёт его в
  символ без всякой проверки) — это закрывает существующий долг
  «`FUNCTION F : Bogus` падает уже в codegen».

### Встроенные конверсии

Таблица `builtins` (имя → типы параметров и тип результата) с `INT_TO_REAL` и
`REAL_TO_INT`. Резолв callee в `checkCall` (`sema.go:267-299`) — порядок
`pous` → `builtins` → `syms`; объявление POU с именем builtin — ошибка
«reserved name». В граф рекурсии builtins не попадают.

### Side-table и контракт

```go
type Info struct {
    Types        map[ast.Expression]TypeKind // тип каждого выражения
    UsedBuiltins map[string]bool             // какие конверсии реально вызваны
}
```

`Check(*ast.SourceFile) []error` → `Check(*ast.SourceFile) (*Info, []error)`.
Это правка зафиксированного контракта — отразить в `CLAUDE.md` на этапе 4.
`UsedBuiltins` бесплатно решает задачу этапа 3: пролог C-файла пишется раньше
тел, а знать про хелпер надо заранее.

Затрагивает: `src/main.go` (одно место), `src/sema/sema_test.go` (хелпер
`check`, `sema_test.go:16-24`), `src/codegen/codegen_test.go`
(`generateExample`, `codegen_test.go:74-97`).

## Этап 3 — codegen

`src/codegen/codegen.go`.

- `cTypes["REAL"] = "float"` (`codegen.go:167-169`). В `cWideTypes` REAL **не
  добавлять**: FOR по REAL отвергнут sema, и ошибка `cWideType` остаётся
  внутренней защитой. `constStepSign` (`codegen.go:667-679`) по той же причине
  не трогаем.
- `Generate(sf, opts)` → `Generate(sf, info *sema.Info, opts)`.
- **Литералы** (`codegen.go:769-770`): `IntLiteral` при
  `info.Types[e] == Real` → `1.0f`, иначе как сейчас; `RealLiteral` → хелпер
  `cFloatLit(v float64) string`: `strconv.FormatFloat(v, 'g', -1, 32)`, и
  **если в результате нет ни `.`, ни `e`/`E` — дописать `.0`** перед суффиксом
  `f` (иначе `2.0` даст `2f`, что в C невалидно), затем `+ "f"`.
- **Нули** — литеральный `0` сейчас в трёх местах (`codegen.go:433`, `:482`,
  `:494`): ввести `zeroLiteral(stType)` → `"0"` / `"0.0f"` и звать её во всех
  трёх.
- **Драйвер** (`codegen.go:544`) — формат по типу поля: `%d` для INT, `%g` для
  REAL (6 значащих цифр, детерминированно; float→double промоушен в varargs
  штатный). Формат печати — часть контракта `.expected`, зафиксировать в
  `CLAUDE.md`.
- **Конверсии** в `g.expr`: `INT_TO_REAL(x)` → `((float)(<x>))`;
  `REAL_TO_INT(x)` → `st_real_to_int(<x>)`. Хелпер эмитится в прологе **только
  при `info.UsedBuiltins["REAL_TO_INT"]`** — иначе `-Wall` даст
  `-Wunused-function` и зашумит `TestGCC`:

```c
static int16_t st_real_to_int(float v) {
    return (int16_t)(v >= 0.0f ? v + 0.5f : v - 0.5f);
}
```

Имя `st_real_to_int` уже несёт префикс `st_`, которым `mapName`
(`codegen.go:221-234`) экранирует зарезервированные имена, так что с
пользовательским именем оно столкнуться не может.

**Регрессионный сигнал этапа:** golden `.c` всех одиннадцати существующих
примеров обязаны остаться **побайтово прежними**. Если `-update` что-то изменил
— в правке ошибка, а не в эталонах.

## Этап 4 — корпус, тесты, документация

- **`examples/real_all.st`** — новый пример: `VAR` с REAL и инициализаторами,
  арифметика и деление, сравнения в `IF`, `INT_TO_REAL`/`REAL_TO_INT`, REAL как
  вход/выход `FUNCTION` и `FUNCTION_BLOCK`, целочисленный `FOR` с накоплением в
  REAL. Значения `.expected` считаются вручную с оглядкой на `%g` (6 значащих
  цифр) — брать величины, точные в двоичном представлении (0.5, 0.25, 2.5),
  чтобы эталон не зависел от округления.
- Эталоны: `src/parser/testdata/real_all.ast` (парсерный `TestGolden` — glob по
  `*.ast`, поэтому файл нужно создать), `src/codegen/testdata/real_all.c` +
  `real_all.expected`, имя дописать в `goldenExamples`
  (`codegen_test.go:46-58` — там явный список).
- **`sema_test.go`** — новая табличная функция `TestReal`: смешение в
  присваивании и в арифметике, условие `IF` не-BOOL, `FOR` по REAL, диапазон
  REAL-литерала, обе конверсии (позитив и неверный тип аргумента),
  нерезолвящийся `ReturnType`, адаптивный литерал (`r : REAL := 0;` и
  `r := 1 / 2;` — позитивные кейсы).
- **`CLAUDE.md`** тем же коммитом: статус и MVP-ограничения, разделы по
  `lexer`/`ast`/`sema`/`codegen`, новые архитектурные решения (слой типов и
  side-table; адаптивный литерал; REAL = `float`; FOR только INT; изменённые
  контракты `Check` и `Generate`; формат `%g` в драйвере). **Снять** долги:
  «числовые литералы только целые» (частично — остаются `16#FF`, `T#1s`,
  типизированные), «условие IF проверяется с целевым типом INT»,
  «`ReturnType` не резолвится». **Добавить** долги: нет `LREAL`; деление на
  `0.0` даёт `inf`/`nan` без диагностики; сравнение REAL через `=` не
  предупреждается (`-Wfloat-equal` не входит в `-Wall`/`-Wextra`).
- **Удалить `PLAN_REAL.md` и `REAL_PROMPTS.md`** тем же коммитом.

## Верификация

После каждого этапа:

```bash
go build ./... && go vet ./...
go test ./...
```

После этапа 3 отдельно — регрессия эталонов:

```bash
go test ./src/codegen -update && git diff --stat src/codegen/testdata
# ожидается: пусто
```

После этапа 4 — полная цепочка руками:

```bash
go run ./src -main -scans 1 -o /tmp/real_all.c examples/real_all.st
gcc -std=c99 -Wall -Wextra /tmp/real_all.c -o /tmp/real_all && /tmp/real_all
diff <(/tmp/real_all) src/codegen/testdata/real_all.expected
```

Плюс негативные случаи — каждый обязан дать ошибку sema с `line:col`, а не
пройти в C:

```bash
printf 'PROGRAM P\nVAR i : INT; r : REAL; END_VAR\ni := r;\nEND_PROGRAM\n' | go run ./src
printf 'PROGRAM P\nVAR i : INT; r : REAL; END_VAR\nr := i + r;\nEND_PROGRAM\n' | go run ./src
printf 'PROGRAM P\nVAR r : REAL; END_VAR\nIF r THEN r := 1.0; END_IF\nEND_PROGRAM\n' | go run ./src
printf 'PROGRAM P\nVAR r : REAL; END_VAR\nFOR r := 1.0 TO 2.0 DO r := r; END_FOR\nEND_PROGRAM\n' | go run ./src
```
